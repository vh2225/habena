# Habena — GitHub-First 1.0 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Get the repo (renamed AgentGuard → Habena) into a genuinely-good, runnable,
honestly-demoable state and publish it on GitHub as the cheapest possible market test.

**Architecture:** Habena is an MCP middleware proxy. An agent connects to Habena's stdio MCP
server (`createMcpServer`); `tools/call` flows through `ProxyDispatcher` (budget → policy →
approval → audit) for the *decision*, then the server layer forwards allowed calls to the
real downstream MCP server via `DownstreamManager.forward()` → `DownstreamClient.callTool()`
(real `@modelcontextprotocol/sdk` client). The vestigial `Forwarder` class is dead code to
be retired.

**Tech Stack:** TypeScript, Node 20+, `@modelcontextprotocol/sdk`, `better-sqlite3`,
`commander`/`chalk`/`inquirer`, Vitest, pnpm workspaces. Web: Next.js.

**Strategy note:** Only **Phase A** (the fairness floor) + **Phase D** (the demo) are
committed work. Phases B/C/E/F are fast-follow, gated on positive GitHub-first reception —
they are intentionally milestone-level here (YAGNI: don't detail what nobody's asked for yet).

**Ground rules:** @superpowers:test-driven-development for every code change.
@superpowers:systematic-debugging for the test-fix task. Frequent commits. Keep the README's
honesty ("early, working, single-operator tested").

### Task A1: Prove end-to-end forwarding with an integration test

**Why:** The earlier worry that "forwarding is stubbed" was wrong — the live stdio path
already forwards. We must *lock that in with a test* so it can't silently regress, and so the
README's "forwards tool calls to the real MCP servers downstream" claim is backed by green CI.

**Files:**
- Create: `packages/core/tests/proxy/forward-e2e.test.ts`
- Reference: `packages/core/src/proxy/server.ts:142-229` (`createMcpServer`)
- Reference: `packages/core/src/downstream/manager.ts:53-63` (`forward`)
- Reference: `packages/core/tests/downstream/manager.test.ts` (existing pattern for a fake
  downstream MCP server — reuse its harness)

**Step 1 — Write the failing test.** Stand up a tiny in-process fake downstream MCP server
(or child-process echo server, following the existing `manager.test.ts` pattern) exposing one
tool `echo(text)`. Build a `DownstreamManager` over it, a permissive `PolicyEngine` that
allows `echo`, wire `createMcpServer`, then issue a `tools/call` for `echo` and assert the
response content comes back from the downstream (e.g. `text: "hello"`), proving the call was
actually forwarded and the result returned — not `result: null`.

**Step 2 — Run it.** `cd packages/core && pnpm vitest run tests/proxy/forward-e2e.test.ts`.
Expected initially: it should **pass** if the live path already forwards (confirming the
correction). If it fails, you've found a real gap — switch to @superpowers:systematic-debugging.

**Step 3 — Commit.** `git commit -m "test(proxy): lock in end-to-end downstream forwarding"`

### Task A2: Retire the vestigial `Forwarder` stub

**Why:** `Forwarder.forward()` throws `"not yet wired"` and is never called for actual
forwarding (the dispatcher only uses `forwarder.routeFor()` for an audit-log label). It's the
source of the "it's stubbed" misconception. Remove it or reduce it to only what's used.

**Files:**
- Modify: `packages/core/src/proxy/forwarder.ts` (delete `forward()`; keep `routeFor`/server
  registry only if still used by the dispatcher, else delete the class)
- Modify: `packages/core/src/proxy/server.ts:101` (the `forwarder.routeFor(...)` audit-label
  call — repoint to `DownstreamManager`/`ToolOwner.server`, which `createMcpServer` already
  knows via `owner.server`, so the dispatcher may not need `Forwarder` at all)
- Modify: `packages/core/src/proxy/server.ts:122-124` (delete the misleading "Phase 1/Phase 2"
  comment and the `result: null` framing)

**Step 1 — Write/adjust the test.** Ensure existing dispatcher tests still pass with the audit
`mcpServer` label sourced from the request (`req.mcpServer`) rather than `forwarder.routeFor`.
Add an assertion that the audit row's `mcpServer` is correct without a `Forwarder`.

**Step 2 — Refactor.** Remove `forward()`; thread the server name through `req.mcpServer`
(already populated by `createMcpServer` at `server.ts:184`). Delete `Forwarder` if fully unused.

**Step 3 — Run the full suite.** `pnpm -F @agentguard/core test`. Expected: green (minus A3's
known failures, fixed next).

**Step 4 — Commit.** `git commit -m "refactor(proxy): retire unused Forwarder stub; audit label from request"`

### Task A3: Fix the 4 failing `policy explain` tests (exit code)

**Why:** `policy explain` is a *trace* command. A `deny` result is a valid answer, not an
error, so it must exit `0`. The suite currently gets exit `1` on deny traces (regression after
Phase 9 V2). Usage errors (no arg / invalid JSON) must still exit `1`.

**Files:**
- Test (spec): `packages/core/tests/policy/policy-explain.test.ts` (4 failing cases)
- Likely fix site: `packages/core/src/cli/commands/policy.ts` (the `explain` action returns
  cleanly today — so the exit `1` comes from elsewhere: an outer CLI error handler in
  `src/cli/index.js`, or `loadHostPolicy()` throwing in the host-policy-floor test setup)

**Step 1 — Reproduce.**
`cd packages/core && pnpm build && pnpm vitest run tests/policy/policy-explain.test.ts`.
Expected: 4 fail, incl. `respects host-policy floor when present` → `expected 1 to be +0`.

**Step 2 — Find the exit-1 source** with @superpowers:systematic-debugging. Candidates, in
order: (a) outer command wrapper in `src/cli/index.ts` that `.catch(() => process.exit(1))`;
(b) `loadHostPolicy()` throwing when a host-policy fixture path is set; (c) a stray
`process.exit` reachable on the deny path. Add a one-line repro outside Vitest:
`node dist/cli/index.js policy explain --json '{"tool":"x","args":{}}'; echo "exit=$?"`.

**Step 3 — Fix minimally.** Ensure a successful trace (any decision) resolves with exit `0`;
preserve exit `1` only for the usage-error branches (`policy.ts:126`).

**Step 4 — Verify.** `pnpm vitest run tests/policy/policy-explain.test.ts` → 4 pass. Then full
suite `pnpm -F @agentguard/core test` → all green.

**Step 5 — Commit.** `git commit -m "fix(cli): policy explain exits 0 on deny traces (only usage errors exit 1)"`

## PHASE B — Threat firewall (fast-follow, reception-gated)

Milestone-level. The "antivirus" half of the wedge; what makes "firewall" credible.

- **B1 — Rug-pull detection.** Hash each downstream tool's `description`+`inputSchema` on first
  sight (persist in SQLite); on a silent change, force re-approval + alert. Directly counters
  the Postmark/rug-pull class.
- **B2 — Tool-poisoning scan.** Heuristics over tool descriptions for injected-instruction
  patterns ("ignore previous", hidden directives, base64 blobs); surface in `security audit`
  and at startup.
- **B3 — Credential-egress rule pack.** Built-in pack flagging tool-call args containing
  secrets/SSH-key/`.env`/token-shaped strings. Counters the Cursor exfil class.
- **B4 — Threat-feed MVP.** Hand-curated blocklist of known-bad MCP servers synced on a
  schedule (decide source: own list vs. reuse mcp-scan's signatures).
